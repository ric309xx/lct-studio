## 開發與驗證

### 點之記與批次下載

點位資料內的「下載點之記」可輸出 PDF、Word（DOCX）或含照片的 HTML。沿用精簡資訊表及位置圖，照片以橫式呈現，直式照片僅在輸出時旋轉，原檔不變；標題使用「點號（近照／遠照）」。預設 1 近照 + 4 遠照，也可選 1 + 1、全部照片或自行勾選。

批次操作：

1. 在點位清單或地圖按「批次點之記」。清單左側的勾選框只用於下載選點；上方資料集勾選仍控制地圖顯示。
2. 清單逐點勾選，或「全選篩選結果」（包含尚未載入清單的結果）。搜尋、切換資料集及切換手機清單／地圖時保留已勾選點位。
3. 按「地圖選點」後，點擊地圖標記可勾選／取消；已選點以橘紅外框標示。相近或重疊點位會開啟可多選的清單，並顯示資料集以區分相同點號。
4. 按「下載已選 N 點」或「下載設定」，選擇「單一 PDF（全部點位合併）」或「ZIP（每點一份檔案）」，並設定底圖及每點照片配置。預設下載一份完整 PDF，各點依序分頁，保留每點的資料、位置圖與照片。ZIP 可選 PDF／Word／HTML，以資料集分資料夾，檔名前加唯一序號，避免同點號覆蓋。
5. ZIP 附「下載清單.csv」，記錄點位 ID、實際照片張數及不足提醒。兩種下載方式在照片不足時皆使用現有照片並顯示提醒；位置圖或附件讀取失敗則不下載本次檔案，勾選保留可重試。可隨時取消產生。

「清空勾選」清除全部下載選點，「結束選點」回到一般查點；重新整理或登出也會清除勾選。地圖與照片生成在瀏覽器逐點處理，不修改點位資料；大量照片的處理時間及可用記憶體依裝置而異。

地圖右下方定位鍵旁的箭頭可選「單次定位」或「持續跟隨」，預設單次定位：只移到目前位置一次，後續 GPS 僅更新標記與距離。選擇持續跟隨後，地圖隨 GPS 移動保持目前位置置中，按鈕顯示「跟隨中」，再按一次可暫停。首次定位至少放大至 16 級，後續定位保留使用者調整的比例；滾輪或雙指縮放結束後仍置中。單指拖曳、搜尋地標、選擇控制點或查看全部點位會暫停跟隨，GPS 仍更新標記與距離；再按「持續跟隨」即可恢復。兩種模式可隨時切換，等待首筆定位時也可取消，延遲回傳不會搶回地圖。右側點位資料可「收合／展開」，保留頁籤與尚未送出的內容。

點之記與批次下載已部署至上方雲端入口。Cloudflare Worker 必須另行部署，Git 推送不會自動更新雲端系統。

`npx.cmd wrangler d1 execute lct-control-points --remote --file schema.sql --config wrangler.production.jsonc`。

Google Drive OAuth 與相機 AR 尚未實作。
手機找點：底部按「找點」，從目前勾選圖層中選最近八點之一；選取後以大字顯示直線距離、北向／羅盤方向及定位精度。也可從點位資料按「開始找點」。本站地圖可繪製直線連線與步行路線，按「規劃步行路線」才將起終點送到 FOSSGIS／OSRM 步行服務；不使用 Google 地圖，不保存找點軌跡。服務不可用時保留直線指引。路線末端不一定在標石上，最後一段依現場通行與照片確認。GPS 超過 30 秒未更新會提示過期。

現場建點：地圖按「新增現場點」或點位清單右上角「＋」，可選既有圖層或新增圖層，以 GPS（保留精度）／地圖點選的 WGS84 概略位置新增，並拍照或選照片。空心虛線圈與「概略」標籤代表尚未測量。新建圖層／點位需要連線，照片先保存至待傳後同步。
後續測量：開啟該點資料，按「補上測量坐標」，填入 TWD97／TWD97[2010]、分帶、N/E、可選高度、高程基準、日期與作業來源。更新同一 ID，保留照片、巡查、原概略位置及稽核歷程；來源匯入成果不透過此功能覆寫。現場新增點的後續測量亦可再次更新。點之記、CSV／GeoJSON 含坐標品質，WGS84 經緯度與 TM2 公尺分別標示。
同號點：清單顯示來源圖層，避免不同圖層的同號點況混淆；「115年測量控制點」為原像控點圖層更名。
`scripts/field-review-server.mjs` 僅供本機隔離驗證，使用模擬 GPS／羅盤及記憶體資料庫；不含正式資料，也不部署。正式版本仍需 iPhone／Safari 實機確認感測器與相機。
圖層選擇：在「資料集篩選」勾選需要顯示的資料集，按「儲存目前圖層」才會保存。下次開啟、重新整理或使用離線資料時，恢復此瀏覽器最後儲存的組合；臨時改勾選不覆蓋設定。可以保存全部取消。自選組合不會自動勾選新增資料集；儲存全部資料集則包含後續新增圖層。設定不跨裝置同步，清除網站資料後需重新儲存。

## 地點搜尋（本機開發）

地圖上方可搜尋地標、路名或地址；選取結果後移動地圖，紅色標記表示搜尋位置。搜尋不更動控制點坐標或資料集篩選。
地點查詢透過登入保護的 `/api/places`，由 Worker 連線 Photon／OpenStreetMap；需要網路，收錄完整度與服務可用性依提供者而異。可加上縣市或行政區縮小結果。
只在使用者按搜尋或 Enter 時查詢，伺服器限制頻率並在私人 R2 快取結果 7 天。`GEOCODER_URL` 可設定相容 Photon 的其他服務端點，預設 `https://photon.komoot.io/api/`。
服務與 API 說明：https://github.com/komoot/photon 、https://github.com/komoot/photon/blob/master/docs/api-v1.md 。
像控點資料集 `image-control-202610` 使用金黃色標記與深色外框，清單圖示、資料集圓點及圖例同步顯示。

地圖近點選取：群聚保留代表點的標記與配色，旁邊以小數字顯示總點數（例如 2 代表兩筆），放大後顯示代表點點號；代表點優先採用控制點或一等水準點，其次為測量點位，標記位於代表點原坐標。點擊數字或相互重疊的點位圖示會列出可選點位，包含資料集、原點號與點況；同點號不同來源不會合併。即使坐標完全相同，仍能分別開啟。清單也提供「放大此範圍」，按 Esc／關閉或點擊地圖空白處可收起。

地圖操作：拖曳與滾輪不要求先取得鍵盤焦點，選點或關閉資料後可直接操作地圖。直接點地圖只開啟資料、保持目前視角；從清單選點立即定位，至少放大至 17 級，已放大更多則保留比例。觸碰／滾輪會中斷尚未完成的導航動畫。群聚圖示依群聚與點號顯示層級快取，資料或群聚更新時重建。

## 現場分類連拍與巡查完成

照片分批操作：開啟點位「照片」→「分類連拍／選擇照片」，先選近照、遠照或其他類別，按「開啟連拍相機」後可重複按「拍一張」，檢查縮圖／移除後按「確認上傳」。例如近照三張確認一批，再重新開啟選遠照拍四張。相機只在主動開啟時請求，離開頁面或關閉對話框即停止影像串流；不支援連拍時可重複使用「系統相機」或多選相簿照片，仍最後整批確認。確認前僅留在此畫面記憶體，關閉／重整會提示；確認後整批以單一 IndexedDB 交易加入待傳，離線可暫存、重連後續傳。新點位表單也使用相同分類連拍，先加入表單，保存點位後才加入待傳。單張上限 30 MB。

找點完成：按「點位存在／找到點了」建立本次巡查，點況立即顯示「已巡查 · 點位存在」，未同步另標待同步。此按鈕不替使用者判斷標石完好；可在巡查頁補充完好／損壞與說明。接著選「拍攝現場照片」或「略過」，整批照片關聯到本次巡查；完成後可繼續拍其他類別或按「下一點」。下一點仍只從勾選圖層的最近八點選擇，排除本次已完成點位；重新開啟找點會開始新的一輪。

事後修改：連線時每張照片下方可按「修改分類」，每筆巡查下方可按「修改此筆巡查」，修改點況與內容。保存時檢查原值避免覆蓋他人修改，並記錄修改前後稽核。照片原檔／拍攝時間、巡查時間／定位保留；點位總點況以時間最新的巡查為準，修改舊紀錄不取代最新狀態。修改後需重新下載離線包，其他裝置既有離線包不會自動改寫。

上方手機圖示為「固定直向」，使用瀏覽器原生螢幕方向鎖定，必要時進入全螢幕，只有 API 成功才顯示固定。iPhone Safari 若未提供／不允許此能力會顯示明確提示，須用控制中心直向鎖定；網站無法強制改變作業系統設定。不以 CSS 旋轉畫面假裝鎖定。API 說明：https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock 。

### DXF 參考圖層

「圖層與工具 → 參考圖層」提供獨立顯示開關、範圍定位、原始 DXF 及含屬性 GeoJSON 下載。線面輪廓以橘色顯示；點圖徵與圖塊屬性保留於轉換檔，不自動配對到輪廓。參考圖層需要登入，原檔存於私有 R2，不打包到公開前端或 Git。

DXF 必須先確認來源 CRS、轉成 WGS84 GeoJSON，再經登入後以 `POST /api/references` multipart 上傳 `source`（DXF，10 MB 內）、`geojson`（5 MB 內）、`metadata`（JSON，含 `name`、`epsg`、可選 `warning`）。目前介面提供檢視與下載，尚未提供瀏覽器直接解析 DXF。`GET /api/references` 列出圖層，`GET /api/references/:id` 取得完整圖徵，`GET /api/references/:id/source` 下載原始檔。來源／轉換內容及 CRS 共同產生識別碼，重試不重複建立。

完整 ZIP 備份及 `check-backup` 還原核對包含參考圖層 metadata、原始 DXF、GeoJSON 與 SHA-256。離線下載會保存轉換圖形；底圖及原始 DXF 下載仍需網路。


### 登入計算與成果年份顯示

密碼仍使用既有 PBKDF2-SHA256（100,000 次）設定。瀏覽器／CLI 在裝置端衍生金鑰，對 120 秒有效的一次性挑戰做 HMAC；Worker 原子消耗挑戰並驗證憑證，保留原有登入速率限制與 HttpOnly 工作階段。避免在 Worker 內執行高成本 PBKDF2 導致 Error 1102。舊版直接送密碼的頁面會提示重新整理；不再由 Worker 執行密碼雜湊。

升級前對既有本機／正式 D1 執行 `migrations/0002_login_challenges.sql`；首次安裝的 `schema.sql` 已包含新表。此表只保存短效登入挑戰，不改動點位資料。資料集顯示名稱依來源 metadata 的 `resultYear` 加上年份前綴，不將坐標年代當成果年份，也不修改資料庫原始名稱。

手機舊分頁若仍送出舊版登入請求，更新後的 Service Worker 會在收到 409 時重新載入該分頁，請再輸入密碼；其他分頁、正常登入與上傳不會觸發重新載入。入口 HTML 與 `sw.js` 不使用 HTTP 快取，回到分頁或恢復連線會檢查更新。離線啟動仍使用目前版本的程式快取；更新只清理舊程式快取，不清除 IndexedDB 的離線資料與待傳照片。

## 跨電腦同步與發布

程式以 GitHub `main` 為共同版本；部署前先取得遠端提交，再合併本機修改。OneDrive 出現電腦名稱結尾的衝突副本時，先備份再比對，不能直接以其中一台覆蓋。此次副本已保存於 `.local/merge-sync-20261014/`，編譯目錄只保留合併後的正式檔名。

控制點、巡查、測量成果與附件以正式 Cloudflare D1／R2 為最新資料來源。換電腦只同步程式，不將舊 `.wrangler` 或舊備份還原至正式站。上方「更新資料」會核對雲端版本；沒有變更時沿用瀏覽器快取。離線包仍需另外重新下載。雲端發布前先備份資料、來源版本及全部 R2 物件，發布後逐欄比對，絕不以點數相同當作資料未變的唯一依據。

兩套功能的驗證使用 `npm run build` 及 `npm test`。網站部署使用 `wrangler deploy --config wrangler.production.jsonc`，此操作只發布程式；不要附帶執行初始化、seed、restore 或資料匯入。既有正式站已具備 `point_revision`，僅全新／舊本機環境才依 README 套用所需 migration。
