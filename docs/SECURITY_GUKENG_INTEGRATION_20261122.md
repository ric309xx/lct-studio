# 古坑整合至官網專案選單

## 觀看操作回歸修正

Worker候選1987fa55已經使用者明確同意並Promote至100%，部署後6項匿名保護檢查通過。使用者已自行在預覽站完成官網管理員登入；實際看到原始模型、兩分區及報告按鈕，但指出左鍵對焦與繞點旋轉沒有保留。

這輪僅修前端預覽：恢復古坑專用的持續ENU旋轉中心、點選後只轉向而不移動相機／縮放、拖曳不誤觸對焦、右鍵平移、觸控旋轉／平移／縮放、正視坡面及分區定位；全域「回到模型」連回古坑全景。量測／框選啟用時導覽讓出點選事件，離開專案完整清除監聽與還原控制器。權限、Secret及Worker不需再次變更。

使用者另表示「在模型上點選點位並將資料匯出dxf，之後可能會需要」。記為後續需求，需保留點位順序並明確核對TWD97/TM2與TWVD2001高程轉換；本輪不冒稱已提供DXF，也不擴大古坑原範圍提報／審核的寫入權限。

使用者明確要求古坑放進原本十幾個專案的同一個選單，不再獨立成外連按鈕；管理員登入後直接切換，不再要求原古坑觀看密碼。

## 預覽候選範圍

- 官網管理員目錄新增`gukeng-slope-20261019`，名稱「古坑｜噴凝土邊坡（20261019）」。原15個選項將變成16個；伺服器projects含12個原模型、3個比較另計。
- 移除獨立古坑外連；桃園案件總覽也改放完整管理專案選單，方便離開總覽切換其他案。
- 在同一個Cesium檢視器保留原始實景、計算坡面、已施作／應施作未施作勾選、既有分區面積及PDF閱讀；切換計算圖層不重設相機。
- 面積直接讀既有20261024分區成果，不重算、不把遮蔽推估改稱實測、不覆寫原資料。
- 此輪整合的是成果觀看。原獨立古坑服務的範圍提報、審核、DXF等寫入／管理API不搬入官網，不把官網管理員自動映射成古坑審核管理員。

## 權限與資料

不新增或複製密碼／Secret，不改古坑原Worker或原登入。共用Worker新增一個唯讀授權交換：只接受既有官網管理員的有效桃園上游Session，發出`gukeng-20261019`唯讀Token；有效期不得超過原Session，直接以密碼登入此新scope一律拒絕。

古坑資料路徑為既有私有bucket內`survey-results/gukeng-20261019/20261021-v7/`。從本機古坑`asset-index.mjs`及`compat-assets.mjs`合併出3458個`model/`及`output/`固定別名；相同alias以compat版本優先，特別保留新版manifest、分區GLB及PDF，避免誤讀舊版package manifest。伺服器才知道R2 key，客戶端不能提交任意prefix。現有資料不重傳／刪除，所有新路徑只接受GET／HEAD。

新R2路徑不接受私人觀看站的舊Cookie，只接受該scope的短效Bearer。其他案件分享Cookie、桃園觀看Token及龍洞服務Token均不取得古坑；官網bootstrap只在管理員真的切到古坑時向Worker交換，原15項日常登入不增加這次交換呼叫。

1. 本機只跑純Node安全測試；沒有在本機啟動esbuild／Vite／Vitest或改防毒。新來源與權限測試已初步通過；雲端完整回歸及TypeScript尚待。
2. 沿用`security-preview-20261118`推預覽建置，main與目前正式版本1d4c93f不動。預覽新古坑選項要等Worker候選部署後才能實際讀取，不能把建置通過當成模型已驗收。
3. 準備完整新Worker及回復點f4fffbc5；對新增「官網管理員可讀古坑成果」的共用Worker部署另做具體確認，再部署及真實預覽驗收。原古坑服務不動，其他客戶權限不擴大。
4. 驗收管理員切換古坑免重登、原始／計算圖層與兩分區、PDF、離開／回到其他案件、刷新及客戶拒絕。確認後才更新main／正式站。
